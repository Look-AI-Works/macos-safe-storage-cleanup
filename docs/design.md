# macOS 安全清理设计

当前版本是一份供大模型使用的技能说明。用户可以只提供「储存空间」里的分类和容量，让模型解释下一步该看哪里。普通会话中，模型负责分析和指引，用户在访达或所属应用中核对并操作。仓库尚未提供本机扫描器或文件回收执行器。完整运行规则见 [SKILL.md](../SKILL.md)。

## 怎样判断一份文件能否处理

| 看到的情况 | 输出 | 下一步 |
| --- | --- | --- |
| 文件属于照片图库、iCloud、系统、备份或正在进行的任务 | 保护或跳过 | 保留原位。遇到云端目录或资料库就停止深入查看。 |
| 某应用明确区分缓存与用户数据 | 原生工具指引 | 让用户打开该应用的管理页面，核对所选类别和影响。若只能连同用户数据清理，就停止。 |
| 文件很大、很旧、同名，或在名为 Cache 的目录内，但用途不明 | 仅报告 | 给出大小及待核对的问题。个人文件即使内容相同，也可能在不同项目里各有用途。 |
| 应用能证明暂存副本来自已结束的任务、成品仍在、副本已无恢复用途 | 有受限执行器时才可确认回收 | 核对规则版本、占用状态、对象身份及该类文件的还原测试。普通会话只解释判断依据。 |

例如，看到“系统数据 80 GB”时，模型应引导用户查看分类和大文件详情。这个数字只代表多种数据的合计，无法据此判断哪些文件冗余。查看入口和分类含义见 [Apple 储存空间指南](https://support.apple.com/zh-cn/102624)。

## 谁来确认，确认什么

**在普通会话中**，用户认出并决定移走某个本地普通文件后，模型才给出访达中的操作步骤。移到废纸篓后，用户仍可选中项目并放回原处。如用户另行决定永久移除其中一项，应在废纸篓核对该项，并在访达中确认该操作。把文件移入废纸篓时，它仍占用磁盘空间。[Apple 储存空间指南](https://support.apple.com/zh-cn/102624)

**如需接入受限执行器**，宿主需在独立界面落实以下顺序。任何一步失效都应保留文件。

1. **预演。** 固定每个文件的身份、所在卷、规则版本及拟执行动作。本地显示完整位置、判断理由、大小和还原方法，所有项目初始未选中。
2. **确认。** 由用户勾选并确认“将所选 N 项移入废纸篓”。一次确认只允许处理当时选择的文件。更改选择、过期或取消后，需要重新预演。
3. **回收。** 逐项复核文件是否仍为原对象、是否又被应用占用。遇到替换、链接、跨卷或身份不明时跳过。回收失败就记录失败并保留文件。
4. **核对。** 分开报告候选大小、成功移入废纸篓的大小、同一卷前后可用空间的实测差值。缺少后一次读数时写“未测”。中断后核对回执，状态未知的项目保留待查。

## 参考过的开源方案

| 项目 | 上游做法 | 本项目采用的设计 |
| --- | --- | --- |
| Mole | 支持清理前预演，并允许用户增加需保护的缓存。部分清理动作会永久删除文件。[官方仓库的安全说明](https://github.com/tw93/Mole#safety) | 预演和保护规则单独设计。回收范围以用户看过并确认的清单为准。 |
| dupeGuru | 为目录区分普通、参考和排除状态。参考目录可参与比对并保护原件，排除目录不参与扫描。[官方目录选择文档](https://github.com/arsenetar/dupeguru/blob/master/help/en/folders.rst) | 先确定范围，再讨论重复项。只在用户授权时本地比对内容，个人资料的重复结果仅供用户查看。 |

## 用模拟数据验收

以下场景用于检查模型回答，接入执行器时也可用作集成验收条件。示例路径、容量和文件状态均为虚构。

| 输入场景 | 应看到的结果 |
| --- | --- |
| 用户只提供分类数据，要求腾出 20 GB | 模型给出下一步查看方法及判断依据。缺少候选证据时，如实报告当前可确认的文件为零。 |
| iCloud 中有两个同名的课程视频，一项显示云朵图标 | 保护同步目录，仅解释图标及同名不足以判重。 |
| 下载目录里有 3 GB 的旧安装镜像，用户尚未说明用途 | 仅报告。请用户核对用途、是否有其他可信副本，以及是否仍需离线安装。 |
| 外部执行器已预演两个暂存副本，用户取消，或其中一项被替换成链接 | 取消时整批不执行。对象被替换时跳过该项，记录原因。 |
| 用户将 800 MB 的文件移入废纸篓，尚未复测可用空间 | 分别报告已移入 800 MB、实际可用空间变化“未测”，并给出放回原处的方法。 |
